# SETLIST — FITNESS APP

Build a mobile-first fitness tracking web app called **Setlist**.

Use **HTML, CSS, and vanilla JavaScript**. Avoid frameworks unless there is a compelling reason to use one.

The app should initially work entirely in the browser using localStorage. Structure the code so a backend such as Firebase could be added later.

The priority is a polished, functional UI and a simple, intuitive workout experience.

---

# 1. APP CONCEPT

Setlist is a simple fitness workout organizer and tracker.

The user chooses what they want to train. Setlist helps them:

* Build workouts
* Start workouts quickly
* Remember previous workouts
* Suggest weights, reps, and sets based on history
* Track weight, reps, and sets
* Estimate workout duration
* Track actual workout time
* Track average rest time
* Track progression
* Build a workout bank
* Track consistency
* Earn XP and levels

The app should NOT feel like a personal trainer or forced training program.

The user remains in control.

Avoid:

* Subscription/paywall features
* Social feeds
* Calorie tracking
* Nutrition tracking
* Forced programs
* AI coaching
* Excessive gamification

---

# 2. CORE PRINCIPLE

The app has three ways to start training:

### QUICK START

"You decide what I'm doing."

The user provides constraints and Setlist builds the workout.

### CREATE WORKOUT

"I'll decide what I'm doing."

The user builds the workout manually.

### REPEAT WORKOUT

"Use something I've already built."

The user selects a workout from their workout bank and modifies it if desired.

---

# 3. MAIN NAVIGATION

Four primary sections:

* Home
* Exercises
* Workouts
* Stats

Use a bottom navigation bar for these sections.

The user should be able to navigate between these sections at any time.

---

# 4. ACTIVE WORKOUT STATE

An active workout is a persistent application state, NOT simply a page.

Once a workout starts:

* The workout timer continues running
* Workout progress is preserved
* Completed sets are preserved
* Entered weight/reps are preserved
* The user can navigate anywhere in the app
* The user can return to the active workout at any time

Navigating away must NOT cancel or pause the workout.

Only an explicit pause, finish, or discard action should change the workout state.

---

When a workout is active, display a persistent bottom bar above the normal navigation.

Example:

────────────────────────────

The bar should:

* Show that a workout is active
* Show elapsed workout time
* Show the current exercise

* Provide a Return button
* Remain visible while navigating Home, Exercises, Workouts, or Stats

The timer must continue running regardless of which section the user is viewing.

# 12. QUICK START

Quick Start should allow the user to select:

### Body part

* Full Body
* Upper Body
* Lower Body
* Core
* Custom

### Duration

Use the onboarding preference by default.

Allow the user to change it.

### Equipment

* Gym/available equipment
* Bodyweight only

Bodyweight-only mode is important.

The generator should consider:

* Favorite exercises
* Available equipment
* Recent exercise history
* Exercises not used recently
* Selected body parts
* Desired workout duration
* Sets/reps
* Estimated exercise duration
* Rest periods

The generator should prioritize favorites while introducing some variety.

Do NOT simply choose the same favorite exercises every time.

Example:

QUICK WORKOUT

Upper Body + Core
~29 min

⭐ KB Row
3 × 10

⭐ KB Press
3 × 8

⭐ Face Pull
3 × 12

🆕 Dead Bug
3 × 10

⭐ Push-up
3 × 12

[ START ]
[ MODIFY ]
[ REGENERATE ]

The requested duration does not need to be exact.

A 30-minute request could reasonably produce a 28–32 minute workout.

---

# 13. QUICK START INTELLIGENCE

The generator should use a simple scoring system rather than random selection.

Consider:

* Favorite status
* How recently the exercise was used
* How frequently the exercise has been used
* Whether the exercise matches selected body parts
* Whether the exercise matches available equipment
* Whether adding it keeps the workout near the desired duration
* Variety between exercises

Favorites should have a strong preference.

Recently used exercises should receive a lower priority.

Exercises not used recently should receive a higher priority.

The goal is:

"Mostly exercises I like, with enough variety that every Quick Start isn't identical."

# 16. SET COMPLETION

When a set is completed:

* Save the set
* Record the completion timestamp
* Update workout progress
* Move to the next set

The app should quietly record elapsed time between completed sets.

The user does NOT need to manually operate a rest timer.

Do not force the user to wait a specific amount of time.

---

# 17. REST TIMER

A rest timer may exist as an optional convenience feature, but it should NOT be required for logging a workout.

The app should always record actual time between completed sets automatically.

The user should be free to rest for as long or as little as they want.

---

# 18. EXERCISE COMPLETION

After completing the final set:

KB ROW ✓

35 lb × 10 × 3

The user should be able to choose what exercise they want to do next.

Do NOT force the next exercise from the original workout order.

Example:

WHAT'S NEXT?

[ KB PRESS ]
[ FACE PULL ]
[ + CHOOSE EXERCISE ]

The original workout order should remain available as a suggestion, but the user controls the execution order.

---

# 19. ADDING / CHANGING EXERCISES DURING A WORKOUT

While a workout is active, the user can:

* Choose another exercise
* Add an exercise
* Skip an exercise
* Change exercise order
* Browse the Exercise Library
* Add an exercise from the library to the current workout

The user should be able to select:

"Do next"

without permanently changing the saved workout template unless they explicitly choose to edit/save the template.

This is important:

### Workout template

What the workout normally contains.

### Active workout

What the user actually decides to do today.

Do not automatically overwrite the template when the active workout changes.

# 20. WORKOUT NAVIGATION

The user must be able to navigate the entire app during an active workout.

They can visit:

* Home
* Exercises
* Workouts
* Stats

The workout continues in the background.

The persistent workout bar remains visible.

Returning to the workout restores the exact active state.

Example:

User is doing:

KB Press — Set 2/3

They navigate to Exercises.

They search for Face Pull.

They add Face Pull as the next exercise.

They return to the workout.

Nothing has been lost.

# 21. ACTIVE WORKOUT STATES

Implement explicit states:

### Not started

Workout template exists but hasn't begun.

### Active

Workout is currently being performed.

### Paused

Only if the user explicitly chooses to pause.

### Completed

Workout has been finalized.

### Discarded

Workout has been intentionally abandoned.

Navigating away does NOT change the state from Active.

# 28. XP AND LEVELS

Use XP as a light motivational feature.

Award XP for things such as:

* Completing workouts
* Completing sets
* Trying new exercises
* Progressing exercises
* Maintaining consistency

Do not make heavier weights the primary way to gain XP.

XP should reward showing up and training consistently.

# 31. LOCAL STORAGE

Use localStorage for the initial version.

Create a clean data-access layer so storage can later be replaced by Firebase or another backend.

The UI should not directly manipulate raw localStorage throughout the application.

---

# 32. UI DESIGN

Mobile-first.

Clean, modern, simple.

Large touch targets.

Clear typography.

Minimal clutter.

The workout screen should be especially easy to use while exercising.

Avoid:

* Excessive animations
* Excessive gradients
* Tiny buttons
* Overly complicated menus
* Excessive cards
* Fake motivational language
* Subscription prompts

The app should feel like a polished utility.

---

# 33. IMPORTANT UX PRINCIPLE

The user should never feel trapped inside a workout.

They can navigate anywhere.

They can change what exercise comes next.

They can add exercises.

They can skip exercises.

They can modify weight/reps/sets.

The app remembers everything.

The persistent workout bar always makes it obvious that a workout is active and provides a fast way back.

Setlist should feel like:

**"I know how I want to train. Setlist makes it easy to organize, remember, and track it."**

**"The app is telling me how I have to train."**
